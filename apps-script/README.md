# Бэкенд Google Apps Script (КАФ'26)

Веб-апп Google Apps Script — серверная часть VK Mini App «КАФ'26». Хранит данные в Google Таблице и отдаёт их фронтенду по HTTP.

## Структура

- `Code.gs` — вся логика веб-аппа (doGet / doPost).
- `appsscript.json` — манифест (timeZone UTC, scopes, настройки веб-аппа).

## Зачем нужен `appsscript.json` и куда его использовать

`appsscript.json` — это **манифест проекта Apps Script**. Он описывает настройки скрипта: часовой пояс, права доступа (scopes), версию рантайма и параметры веб-аппа.

### Содержимое файла

```json
{
  "timeZone": "UTC",
  "dependencies": {},
  "exceptionLogging": "STACKDRIVER",
  "runtimeVersion": "V8",
  "oauthScopes": [
    "https://www.googleapis.com/auth/spreadsheets",
    "https://www.googleapis.com/auth/script.external_request"
  ],
  "webapp": {
    "executeAs": "USER_DEPLOYING",
    "access": "ANYONE_ANONYMOUS"
  }
}
```

### Что означает каждое поле

| Поле | Значение | Зачем |
|------|----------|-------|
| `timeZone` | `"UTC"` | Часовой пояс скрипта. **Важно:** должен быть UTC, чтобы время в таблице и `serverTime` считались корректно. |
| `runtimeVersion` | `"V8"` | Современный рантайм Apps Script (V8). |
| `oauthScopes` | список URL | Права доступа. `spreadsheets` — чтение/запись таблицы, `script.external_request` — внешние запросы. |
| `webapp.executeAs` | `"USER_DEPLOYING"` | Веб-апп выполняется от имени владельца скрипта (нужно для доступа к таблице). |
| `webapp.access` | `"ANYONE_ANONYMOUS"` | Доступ к веб-аппу без авторизации (анонимно) — чтобы фронтенд мог обращаться без логина. |

### Куда его использовать

`appsscript.json` — это манифест проекта. Он **не добавляется как файл** в редакторе (кнопка «+» создаёт только `.gs`-файлы). Манифест редактируется отдельно.

### Как применить манифест и Code.gs в проекте

**Способ 1 — через Project Settings (в интерфейсе):**
1. Откройте script.google.com → создайте новый проект.
2. В редакторе удалите стандартный `Code.gs` и вставьте содержимое нашего `apps-script/Code.gs`.
3. Откройте **Project Settings** (значок шестерёнки в левом меню).
4. В разделе **Manifest** нажмите **Edit project settings** (или переключите на вкладку «Manifest»).
5. Скопируйте и вставьте содержимое нашего `apps-script/appsscript.json` в поле манифеста.
6. Сохраните.
7. Привяжите скрипт к таблице (см. ниже).

> **Важно:** кнопка «+» → Script в редакторе создаёт `.gs`-файл, а не `.json`. Манифест — это отдельная сущность, доступная только через Project Settings.

**Способ 2 — через clasp (CLI):**
```bash
npm install -g @google/clasp
clasp login
clasp create --title "KAF26-backend" --type standalone
# скопируйте Code.gs и appsscript.json в папку проекта
clasp push
```
При использовании `clasp` манифест подхватывается автоматически — файл `appsscript.json` в корне проекта будет загружен на сервер.

> **Какой способ выбрать:** если вы не планируете использовать CLI и работаете только через браузер — используйте **Способ 1** (Project Settings). Если хотите автоматизировать деплой — **Способ 2** (clasp).

## Требования к Google Таблице

Таблица должна содержать листы с **точными названиями** (регистр важен): `площадки`, `вопросы`, `отзывы`, `версия кеша`.

> **Важно:** первая строка каждого листа — это **заголовки** (имена колонок). Данные начинаются со второй строки. Код читает данные по именам заголовков, поэтому заголовки должны совпадать с таблицами ниже **по буквам**.

### Лист «площадки»

Заголовки (первая строка):

| id | name | subtitle | location | time_start | time_end | speaker | speaker_title | description | avatar_url | card_avatar_url |
|----|------|----------|----------|------------|----------|---------|---------------|-------------|------------|-----------------|

Формат ячеек:

| Колонка | Тип | Обязательна | Формат / пример |
|---------|-----|-------------|-----------------|
| `id` | текст | да | Уникальный идентификатор площадки. Используется в хэш-роутинге `#<id>`. Пример: `main-hall`, `workshop-1` |
| `name` | текст | да | Название площадки. Пример: `Главный зал` |
| `subtitle` | текст | нет | Подзаголовок. Пример: `Лекции и доклады` |
| `location` | текст | нет | Место проведения. Пример: `Конференц-зал, 2 этаж` |
| `time_start` | текст (ISO 8601 UTC) | да | Начало. **Формат:** `ГГГГ-ММ-ДДTЧЧ:ММ:00Z` (буква `T` и `Z` обязательны). Пример: `2026-09-01T04:00:00Z` |
| `time_end` | текст (ISO 8601 UTC) | да | Конец. Тот же формат. Пример: `2026-09-01T06:00:00Z` |
| `speaker` | текст | нет | Имя ведущего/спикера. Пример: `Иван Петров` |
| `speaker_title` | текст | нет | Регалии/должность. Пример: `Астроном, к.ф.-м.н.` |
| `description` | текст (Markdown) | нет | Описание площадки. Поддерживает Markdown: `#`, `**жирный**`, `- списки`, ссылки. Пример: `**Тема:** тёмная материя\n\n- Вопросы\n- Ответы` |
| `avatar_url` | текст (URL) | нет | Прямая ссылка на картинку (аватар). Пример: `https://example.com/avatar.png` |
| `card_avatar_url` | текст (URL) | нет | Аватар для карточки расписания (главный экран). Если пусто — используется `avatar_url`. Пример: `https://example.com/card.png` |

**Пример заполненной строки (строка 2):**

| id | name | subtitle | location | time_start | time_end | speaker | speaker_title | description | avatar_url | card_avatar_url |
|----|------|----------|----------|------------|----------|---------|---------------|-------------|------------|-----------------|
| `main-hall` | `Главный зал` | `Лекции` | `Конференц-зал` | `2026-09-01T04:00:00Z` | `2026-09-01T06:00:00Z` | `Иван Петров` | `к.ф.-м.н.` | `**Тема:** тёмная материя` | `https://.../avatar.png` | `https://.../card.png` |

> **Про время:** время хранится в UTC (по Гринвичу). Если форум идёт в Красноярске (UTC+7), то для начала в 11:00 по местному времени нужно записать `2026-09-01T04:00:00Z` (11:00 − 7 часов). Приложение само переведёт время в локальный часовой пояс пользователя.

### Лист «вопросы»

Заголовки (первая строка):

| id | platform_id | vk_user_id | name | text | rating | created_at |
|----|-------------|------------|------|------|--------|------------|

Формат ячеек:

| Колонка | Тип | Обязательна | Формат / пример |
|---------|-----|-------------|-----------------|
| `id` | текст | да | Уникальный id вопроса (генерируется кодом). Пример: `uuid-строка` |
| `platform_id` | текст | да | ID площадки (должен совпадать с `id` на листе «площадки»). Пример: `main-hall` |
| `vk_user_id` | текст | да | Идентификатор автора (vk_user_id или fallback). Пример: `123456789` |
| `name` | текст | да | Имя автора. Пример: `Иван` |
| `text` | текст | да | Текст вопроса. Пример: `Будет ли трансляция?` |
| `rating` | число 1–5 | нет | Оценка. **Пустая ячейка** = оценка не поставлена. Пример: `5` |
| `created_at` | текст (ISO 8601 UTC) | да | Время создания (генерируется кодом). Пример: `2026-09-01T04:30:00Z` |

> **Важно:** лист «вопросы» заполняется **автоматически** приложением (когда пользователь задаёт вопрос). Вручную его заполнять не нужно — только для отладки/администрирования.

### Лист «отзывы»

Заголовки (первая строка):

| id | platform_id | vk_user_id | name | text | rating | created_at |
|----|-------------|------------|------|------|--------|------------|

Формат ячеек:

| Колонка | Тип | Обязательна | Формат / пример |
|---------|-----|-------------|-----------------|
| `id` | текст | да | Уникальный id отзыва (генерируется кодом). |
| `platform_id` | текст | да | ID площадки. Пример: `main-hall` |
| `vk_user_id` | текст | да | Идентификатор автора. Пример: `123456789` |
| `name` | текст | да | Имя автора. Пример: `Мария` |
| `text` | текст | да | Текст отзыва. Пример: `Отличная лекция!` |
| `rating` | число 1–5 | **да** | Оценка. **Обязательна** для отзыва. Пример: `5` |
| `created_at` | текст (ISO 8601 UTC) | да | Время создания (генерируется кодом). |

> Лист «отзывы» тоже заполняется **автоматически** приложением.

### Служебный лист «версия кеша»

Этот лист нужен для принудительного обновления расписания у пользователей.

- Ячейка `A1` — строка версии кеша.
- **Формат:** любая строка, например `2026-09-01` или `v3`.
- **Как работает:** приложение кэширует расписание на 2 часа. Если вы изменили расписание и хотите, чтобы пользователи сразу увидели изменения — **измените значение в `A1`** (например, поставьте новую дату). Клиенты заметят смену версии и перезагрузят данные.

**Пример:** лист «версия кеша» с одной ячейкой:

| A |
|---|
| `2026-09-01` |

> Если ячейка `A1` пустая — версия кеша считается пустой, и расписание будет обновляться только по истечении 2 часов.

## Развёртывание веб-аппа

1. Откройте `Code.gs` в редакторе Apps Script (script.google.com).
2. Вставьте код `Code.gs` и `appsscript.json`.
3. Привяжите скрипт к вашей Google Таблице (Ресурсы → Привязать скрипт, или создайте скрипт из таблицы).
4. Нажмите **Deploy → New deployment**.
5. Выберите тип **Web app**.
6. **Execute as:** `Me` (владелец скрипта).
7. **Who has access:** `Anyone` (анонимный доступ).
8. Скопируйте URL веб-аппа — он понадобится фронтенду (`NEXT_PUBLIC_APPS_SCRIPT_URL`).

## API

### GET

- `?action=schedule` — все площадки + `cacheVersion` + `serverTime` (UTC epoch ms).
- `?action=platform&id=X&vk_user_id=Y` — площадка + вопросы пользователя Y.
- `?action=questions&platform_id=X&vk_user_id=Y` — вопросы пользователя Y по площадке X.

### POST (JSON в теле)

- `{ action: 'add_question', platform_id, vk_user_id, name, text, rating? }`
- `{ action: 'edit_question', id, vk_user_id, name, text, rating? }` — только автор.
- `{ action: 'delete_question', id, vk_user_id }` — только автор, физическое удаление.
- `{ action: 'add_review', platform_id, vk_user_id, name, text, rating }`

Ответы — JSON вида `{ ok: true, data: ... }` или `{ ok: false, error: '...' }`.

## Логирование

На каждом шаге вызываются `Logger.log` / `console.log`. Логи смотрите в **Выполнения (Executions)** редактора Apps Script.
