# Общие правила проекта и агентского процесса

## Назначение

В проекте используются два режима работы OpenCode:

- `planner` — анализирует запрос, исследует кодовую базу, уточняет требования и готовит план.
- `executor` — реализует только утверждённый план из `.agents/plan.md` и конкретные задачи из `.agents/tasks.md`.

Никогда не смешивай роли:
- планировщик не реализует код задачи;
- исполнитель не меняет утверждённые требования или архитектурный план без возврата к планировщику.

## Источники истины

Перед работой агент обязан прочитать:

1. `AGENTS.md`;
2. `.agents/plan.md`;
3. `.agents/tasks.md`;
4. `.agents/changelog.md`;
5. `package.json`;
6. документацию, которая прямо указана в плане или задачах.

Если документы противоречат друг другу, приоритет такой:

1. Последнее явное сообщение пользователя.
2. Утверждённый план в `.agents/plan.md`.
3. Текущие задачи в `.agents/tasks.md`.
4. Этот `AGENTS.md`.
5. Архитектура и существующий код.

## Безопасность

- Не читай, не изменяй, не выводи и не коммить `.env`, `.env.*`, ключи, токены, cookies, credentials, приватные сертификаты и секреты.
- Не добавляй секреты в код, документацию, журнал изменений, коммиты или сообщения.
- Не выполняй force push.
- Не удаляй файлы, каталоги, зависимости, CI/CD или production-конфигурацию без явной необходимости, указанной в утверждённом плане.
- Не используй `git reset --hard` и `git clean`, кроме случая отдельного одобрения пользователя.
- Не меняй GitHub Pages, GitHub Actions, домены, secrets и настройки репозитория без прямой команды пользователя.

## Git-процесс

### Ветки

- `main` и `master` — защищённые ветки. Не вноси в них код напрямую.
- Любая реализация выполняется только в ветке формата:
  ```text
  ai/feature-<краткое-название>
  ai/fix-<краткое-название>
  ai/refactor-<краткое-название>
  ```
- Перед изменениями выполни:
  ```bash
  git status
  git branch --show-current
  git fetch origin
  ```
- Если текущая ветка `main` или `master`, создай новую `ai/...` ветку от актуального `origin/main`.
- Если текущая ветка уже `ai/...`, продолжай работу в ней только если она относится к текущей задаче. Иначе создай новую.

### Коммиты и push

- Разрешено создавать осмысленные коммиты только с изменениями текущей задачи.
- Перед коммитом проверь:
  ```bash
  git status
  git diff --check
  git diff --stat
  ```
- Не делай `git add .`, если в рабочем дереве есть несвязанные изменения. Добавляй только файлы текущей задачи.
- Сообщение коммита:
  ```text
  feat: ...
  fix: ...
  refactor: ...
  docs: ...
  chore: ...
  ```
- Разрешено пушить только ветки `ai/...`:
  ```bash
  git push -u origin HEAD
  ```
- Никогда не пушь в `main` или `master` без подтверждения пользователя.

### Применение в main

Когда пользователь прямо говорит: «всё нормально», «можно в main», «подготовь к слиянию» или эквивалентно:

1. Не меняй `main` немедленно.
2. Проверь текущую ветку, рабочее дерево и diff относительно `origin/main`.
3. Запусти финальные проверки.
4. Обнови `.agents/changelog.md`.
5. Создай финальный коммит и push текущей ветки `ai/...`, если это ещё не сделано.
6. Покажи пользователю краткую сводку: ветка, commit SHA, изменённые файлы, команды проверок и результат.
7. Создай Pull Request в `main`, если пользователь это явно разрешил.
8. Перед merge или любым push в `main` дождись отдельного подтверждения пользователя.
9. После merge проверь статус CI/CD и GitHub Pages, если это относится к проекту.

## Качество кода

- Сохраняй существующую архитектуру, соглашения именования и форматирование.
- Используй строгий TypeScript. Не добавляй `any`, `@ts-ignore` или отключения линтера без технического обоснования.
- Не меняй публичные API, схемы данных и контракты без отражения в плане и задачах.
- Не добавляй зависимости, если можно решить задачу средствами текущего стека.
- Изменяй минимально необходимое количество файлов.
- Не выполняй hotfix без плана. Любое изменение проходит через планировщик и `.agents/tasks.md`.

## Проверка

После каждой задачи исполнитель обязан запускать только доступные в `package.json` команды:

```bash
npm run lint
npx tsc --noEmit
npm test
npm run build
```

Если команды нет, не считай это ошибкой: зафиксируй в changelog, что она отсутствует.

## Документация агента

- `.agents/plan.md` — утверждённый план, границы и архитектурные решения.
- `.agents/tasks.md` — исполнимые задачи с контекстом, путями и критериями готовности.
- `.agents/changelog.md` — неизменяемая история выполненных работ, проверок, коммитов и известных ограничений.
- Эти файлы коммитятся вместе с соответствующей работой.
- Не удаляй историю из `.agents/changelog.md`; добавляй новые записи в начало файла.
