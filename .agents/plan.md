### PLAN-20260901-03 — Исправления после ручного тестирования: навигация, авторизация, оптимизация (выполнен)

**Статус:** `completed`  
**Утверждён:** 2026-09-03  
**Завершён:** 2026-09-03  
**Ветка:** `ai/test-plan2`  
**Коммит:** `c9c71f9`

**Задача:** Исправить 8+ проблем, выявленных при ручном тестировании:
1. История навигации приложения (sessionStorage) + кнопка «назад».
2. Кнопки «редактировать»/«удалить» на странице площадки → унифицированная страница редактирования (AskScreen).
3. Таймаут VK bridge (3–5 сек) для работы без VK.
4. Авторизация: всегда показывать auth screen перед отправкой (явное согласие).
5. Карточка без аватара — блок перестраивается.
6. Стрелка назад — центрирование.
7. Шрифты, центрирование, проверка Content-Type.
8. Анализ и оптимизация скорости (сетевые + внутренние).

**Решения:**
- История навигации: стек в `sessionStorage`, `navigate()` вызывает `pushNavigation()`.
- Кнопка «назад»: `goBack()` извлекает последний маршрут из стека; fallback на расписание.
- Кнопки ред./удал.: на странице площадки → AskScreen в режиме editing.
- Таймаут VK bridge: `Promise.race` с 3–5 сек; fallback на localStorage / анонимный профиль.
- Авторизация: auth-gate всегда (даже если профиль сохранён).
- Avatar: `null` без URL; карточка перестраивается через flex.
- Стрелка: `line-height: 1` для точного центрирования.

**Декомпозиция задач:** см. `.agents/tasks.md` (TASK-20260901-18 … TASK-20260901-25).

### PLAN-20260901-02 — UI-баги: тулбар главного экрана, аватарки, экран отзыва (выполнен)

**Статус:** `completed`  
**Утверждён:** 2026-09-01  
**Ветка:** `ai/feature-kaf-feedback`

**Задача:** Исправить 6 UI-багов в трёх экранах:
1. Главный экран — закреплённый полупрозрачный тулбар (liquid glass) с «КАФ» по центру большим шрифтом и «только сегодня» (без кнопки «Войти»).
2. Главный экран — увеличить мелкие и нечитаемые надписи.
3. Главный экран — аватарка карточки из отдельной колонки `card_avatar_url` (не из `avatar_url`).
4. Экран площадки — аватарка рядом с именем докладчика (`speaker`), а не с названием; использовать `avatar_url`.
5. Экран площадки — описание выделить в белую рамку со скруглениями (`kaf-glass`).
6. Экран отзыва — центрировать «Имя», «Отзыв» и звёзды; увеличить размер звёзд.

**Решения:**
- Тулбар — только на главном экране (остальные экраны сохраняют `AppShell`-заголовок). Кнопки «Войти» в тулбаре нет.
- Центрирование полей и звёзд — только на экране отзыва.
- Новая колонка `card_avatar_url` в листе «площадки»; при отсутствии — placeholder.
- CORS на POST: отправлять `Content-Type: text/plain` (простой запрос, без preflight), GAS-код не меняется.
- Авторизация: появляется только при открытии «задать вопрос»/«оставить отзыв» (auth-gate); имя подтягивается из VK и подставляется в форму.
- TASK-01, 03, 04, 14 затрагивают общие файлы — выполняются последовательно; TASK-02, 13 (без общих файлов) — параллельно.
- Тесты: `lib/router.ts`, `lib/storage.ts`, `lib/identity.ts` (jsdom); `lib/api.ts` (fetch mock); компоненты `StatusView`, `StarRating`, `Avatar`, `QuestionForm`, `ReviewForm` (testing-library).

### PLAN-20260901-01 — VK Mini App «КАФ'26» (выполнен)

**Статус:** `completed`  
**Утверждён:** 2026-09-01  
**Ветка:** `ai/feature-kaf-feedback`

**Задача:** Разработать VK Mini App для Красноярского астрономического форума «КАФ'26»: расписание площадок, вопросы и отзывы, авторизация через VK ID.

**Стек:**
- Фронтенд: Next.js (TypeScript), статический экспорт, многоэкранный SPA с хэш-роутингом, мобильная адаптация.
- UI: `@vkontakte/vkui` (тема liquid glass) + `@vkontakte/icons` + кастомный CSS. Markdown: `react-markdown`.
- Бэкенд: Google Apps Script (веб-апп), данные в Google Таблице (листы «площадки», «вопросы», «отзывы», служебная «версия кеша»).
- Публикация: GitHub Pages (корень домена, без basePath).

**Решения (подтверждены пользователем):**
1. Время в таблице — ISO 8601 UTC без смещения. GAS нормализует в UTC epoch ms.
2. UI — VKUI + кастомный CSS liquid glass.
3. GitHub Pages — корень домена (без basePath).
4. ID VK Mini App — плейсхолдер/переменная окружения (`NEXT_PUBLIC_VK_APP_ID`).

**Ключевые архитектурные решения:**
- Хэш-роутинг: глубокая ссылка `vk.com/app<id>#<platformId>`. Решает проблему динамических маршрутов при статическом экспорте (ID площадок неизвестны на сборке).
- «Сейчас» = `serverTime` (UTC) из GAS (время с сети, не с телефона).
- Активность: `time_start <= serverTime < time_end` (UTC). Может быть несколько активных одновременно.
- Фильтр «текущий день» — локальная дата пользователя = serverTime + смещение часового пояса устройства.
- Кэш расписания в localStorage (2ч) + принудительное обновление по «версии кеша».
- Идентификация: `vk_user_id` из launch params (vk-bridge), fallback на localStorage. Защита от подмены не требуется.
- Права на вопрос: редактирование/удаление только если `vk_user_id` вопроса == `vk_user_id` клиента. Удаление — физическое.
- Задержка отправок (вопрос/отзыв) — минимум 10 секунд (клиент + GAS).
- Максимум логов (`Logger.log`/`console.log`) на ранних этапах.

**Границы scope:**
- Только GAS + Google Таблица на бэкенде.
- Только GitHub Pages на фронте.
- Работа внутри VK Mini Apps на мобильных.
- Вопросы/отзывы — простой текст и цифры.
- Несколько вопросов и отзывов от одного пользователя на площадку разрешены.
- Отзывы — без редактирования/удаления.
